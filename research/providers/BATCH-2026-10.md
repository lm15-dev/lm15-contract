# Batch 2026-10 — the services Pi and LiteLLM both carry

The first expansion batch (research/landscape/REPORT.md, 2026-10-02): every
service both upstream libraries support that lm15 does not. Each has a
`<id>/candidate.json` and a dossier skeleton (`survey.py init`). What was
checked without an account, 2026-10-02:

- **Address**: `POST <base_url>/chat/completions` with no key. A JSON 401
  means a Chat Completions endpoint exists there.
- **Browser**: a CORS preflight from `https://lm15.dev`. An allow-origin
  means the website can call it without the relay.
- **Key variable**: whether the provider's docs page names it.

## Once a key exists

```sh
# 1. the key in ../.env (simple NAME=value; never committed, never printed)
# 2. pick the model roles from what the server serves
python3 research/providers/survey.py models cerebras --env-file ../.env
#    edit cerebras/candidate.json: models.plain (+ reasoner/off/replayer/always_on), delete _review
# 3. the terms first (playbooks/provider.md § 3): freeze them under cerebras/sources/, write the verdict
# 4. the survey (~45 small requests), then the report
python3 research/providers/survey.py run cerebras --env-file ../.env
python3 research/providers/survey.py report cerebras
# 5. a host with many model families: sweep them, two samples each (the worst sample decides)
python3 research/providers/survey.py sweep cerebras --models a,b,c --env-file ../.env
python3 research/providers/survey.py sweep cerebras --models a,b,c --env-file ../.env --repeat 2
python3 research/providers/survey.py report cerebras
```

`cerebras/SURVEY.md` then holds the drafted preset, the decisions only you can make, and the code to
paste; the playbook's remaining steps (live captures, support matrix, tables, ports, website) follow
unchanged.
