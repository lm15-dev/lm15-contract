## 2. OpenAI explicit prompt-cache breakpoints (gpt-5.6+)

Both OpenAI dialects gained `prompt_cache_breakpoint: {"mode":
"explicit"}` on text content blocks (Responses `input_text`, Chat
`ChatCompletionContentPartText`) plus a request-level
`prompt_cache_options: {mode: implicit|explicit, ttl: "30m"}`. This is
Anthropic's `cache_control` model arriving on OpenAI.

Mapping (both dialects, active only when the compat policy's
`cache_control` is `"openai"`, same gate as `prompt_cache_key`):

- `CacheConfig.prefix_until_index = N` → `prompt_cache_breakpoint` on the
  last text block of `messages[N]`. Index clamps to the last message (the
  Anthropic adapter's precedent). The chat dialect forces the array
  content form for that message (a breakpoint cannot ride on a bare
  string).
- `messages[N]` is assistant or tool, or does not end with a text block
  → `UnsupportedFeatureError`. The wire carries breakpoints on input text
  only; moving the boundary silently would change what is cached.
- `prompt_cache_options` is NOT sent. `implicit` is the server default
  and creates one implicit breakpoint besides up to three explicit ones;
  the canonical model has no knob to disable implicit caching and
  inventing one is a separate decision.
- No client-side model gating: pre-5.6 models reject the field with a
  clear HTTP 400 (below). The loud failure is the contract, exactly as
  MAP-5 treats reasoning-off on models that cannot disable it.

Receipts (live, api.openai.com, gpt-5.6-sol, ~3k-token prefix +
`reasoning.effort: none`, `max_output_tokens: 16`):

## 6. Caching, the harmonized picture (observation, no rule change yet)

Live probes for the cache model behind `CacheConfig`:

- Gemini implicit caching (no `cachedContent`, same ~3k-token prefix,
  gemini-2.5-flash and gemini-3.7-flash): 1 hit in 9 calls
  (`cachedContentTokenCount == 3065` on one call, absent on the others).
  Real, best-effort, not guaranteed.
- OpenAI explicit breakpoints: deterministic write-then-read (above).
- xAI: automatic (`prompt_tokens_details.cached_tokens == 512` on a cold
  643-token prompt), no knob.

Every provider now has two tiers: an automatic best-effort tier (OpenAI
implicit, Gemini implicit, xAI automatic; Anthropic requires a marker but
no resource) and a guaranteed tier (OpenAI/Anthropic breakpoints;
Gemini's `cachedContents` resource, the only one needing a side channel).
`CacheConfig(mode="auto")` should mean the automatic tier everywhere.
Today the Gemini adapter answers `auto` with a hidden `cachedContents`
POST on every multi-turn request (`resolve_prompt_cache`), keyed by a
hash of the whole prefix, so every turn creates a new billed resource and
nothing is reused; below the token minimum the POST fails and is
swallowed. This entry does NOT change that behaviour. Proposed rule for
a separate ratification: `auto` sends nothing on Gemini; `retention`/`key`
on Gemini either raise or use an explicit, listable cache-resource
surface (the files precedent). See `lm15-dev/THEORY.md` F1.
