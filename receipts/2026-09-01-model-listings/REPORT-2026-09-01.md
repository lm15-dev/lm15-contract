## Drift found (evidence-backed)

### Endpoint parameters (doc_drift against today's docs)

The `conformance/check_doc_drift.py` tool read its own April-29 copy of
the docs and reported 0. Fed today's scrape it reports 3:

1. **Gemini `serviceTier`** (`unspecified|standard|flex|priority`), a
   top-level request field and an output-only usage field. lm15's Gemini
   adapter RAISES on `Config.service_tier` with "GenerateContent has no
   service-tier field". That message is now false. Fix: map
   `service_tier` → `serviceTier` and read `usageMetadata.serviceTier`
   into `provider_data`. Needs a live receipt (one small request with
   `serviceTier: "flex"`).
2. **OpenAI `prompt_cache_options` `{mode: implicit|explicit, ttl: "30m"}`**
   and per-content-block **`prompt_cache_breakpoint: {mode: "explicit"}`**,
   for `gpt-5.6` and later. This is Anthropic's breakpoint model arriving
   on OpenAI. Consequence for the harmonized cache theory:
   `CacheConfig.prefix_until_index` now has a wire slot on OpenAI (a
   breakpoint on the last content block of that message), and
   `mode="auto"` maps to OpenAI's `implicit` default. Needs a live
   receipt on a 5.6 model with a >1024-token prefix.
3. **OpenAI `moderation` `{model, policy}`**. Provider-specific; belongs
   in `extensions` with a blessed verdict, not in `Config`.

### xAI facts from docs.x.ai (not yet receipted)

- "`logprobs` and `top_logprobs` are not supported by models `grok-4.20`
  and newer. These fields will be silently ignored if set." lm15's
  `XaiLM` inherits the chat dialect's logprobs mapping and therefore
  sends a field the server silently ignores. Per MAP-5's principle,
  `XaiLM` should raise on `Config.logprobs`, as it does for
  `reasoning=off`. One-line change plus a test.
- xAI has a Batch API ("not every model accepts it"). lm15's xAI
  manifest declares `batches=False`. Candidate for a fixture-first
  addition.
- Voice API exists (`grok-voice-think-fast-2.0`). Out of scope today.
