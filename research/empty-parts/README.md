# Empty parts and another dialect's state in a history (MAP-24)

Design pass of 2026-11-11 for lm15-contract issue #3, by
`playbooks/design-pass.md`. The decision is
`changes/2026-11-11-empty-parts.md`; the rule is MAP-24 in
`docs/mapping-rules.md`. Everything here points at a receipt
(`receipts/2026-11-11-empty-parts/`) or a dated page (`sources/`).

Rerun (step 10): `python3 research/providers/empty_parts.py --probe` and
`--replay`, keys in the environment. Re-check when a provider is added or
a dialect builder changes, and by 2027-05.

## Frame, without provider words

A caller keeps a conversation and sends it again. Between two sends the
caller may change model. The conversation holds parts a model wrote and
lm15 read, among them parts with no words: thinking the provider kept to
itself (no text, plus a blob only that provider can read), a reply that
ended before any word, an assistant turn another library recorded as
null.

- The caller controls: which model the next request goes to.
- The caller observes: the next request works, and the model sees
  everything said so far that it can read.
- Must never happen: a part lm15 itself read makes a later request fail;
  lm15 writes words nobody wrote; lm15 forgets a part the first provider
  will need when the conversation returns to it.

## What the references say

- Anthropic, Messages (`scrapes/anthropic/pages/messages--create.md`):
  `TextBlockParam.text` is `minLength: 1`, in a message and in `system`
  (lines 92 and 1273 of the committed scrape); "Consecutive `user` or
  `assistant` turns in your request will be combined into a single turn"
  (line 35).
- Anthropic, thinking (`sources/anthropic-thinking.md`): with `display:
  "omitted"` a thinking block has an empty `thinking` field and its
  signature and is passed back unchanged; "Mid-turn conflicts degrade
  gracefully ... the API doesn't error. Instead, it silently disables
  thinking for that request."
- OpenAI, Chat Completions (`scrapes/openai/pages/chat--create.md` line
  291): assistant content is "Required unless `tool_calls` or
  `function_call` is specified."
- Google (`sources/vertex-thought-signatures.html`): on Gemini 3 "omitting
  a required thought_signature for the first functionCall part in any
  step of the current turn results in a 400 error. A turn begins with the
  most recent user message that is not a functionResponse"; for calls
  "not generated by the API ... (for example, when transferring history
  from a model that does not include thought signatures) ... You can set
  thought_signature to skip_thought_signature_validator, but, this should
  be a last resort".

   seven answer (c18).

## Prior art

pi-ai 0.84.2 (`@earendil-works/pi-ai`, read from the installed package,
`dist/api/`), a client that also sends one history to many providers:
`transform-messages.js` drops a thinking block with no text when the
model differs and turns one with text into text; `anthropic-messages.js`
skips text blocks that are empty or whitespace and messages left with no
block; `google-shared.js` skips empty text "unless they carry a thought
signature"; `openai-completions.js` skips "assistant messages that have
no content and no tool calls. Some providers require 'either content or
tool_calls, but not none'". The same four choices, reached
independently. Prior art is not authority (AUTHORITY.md); the receipts
are.

## Attack (self-review; no second agent ran this)

- **Cold learner.** "I sent five messages and the provider got three."
  The two missing ones had nothing in them; `plan()` shows no adaptation
  because nothing was changed. The rule's first sentence is the answer.
- **Library author on top** (FunctAI, lmcc store recorded messages and
  replay them verbatim; lmcc does not know the provider). Nothing to do:
  the history stays whole, the wire is pruned per dialect at send time,
  so a stored conversation that was stuck works again and going back to
  the first provider still replays its state.
- **Port implementer.** The rule is an equivalence, checked mechanically
  (`same_as`), so corner cases need no judgment: string or array form,
  joining newlines, a developer prefix. Traps found while writing the
  reference: a lone text part beside an empty one must stay a string on
  Chat Completions; Gemini's `functionResponse.response` must be `{}`,
  not `{"result": ""}`, when an empty text sits beside media; a cache
  mark asked for by message index must not shift.
- **Cost accountant.** Fewer bytes on the wire, none added. Prompt-cache
  prefixes change for a history that used to carry empty blocks on a
  server that accepted them (Gemini, OpenAI): one cache miss after the
  upgrade.
- **Provider-switcher mid-conversation.** Between turns: works. In the
  middle of a tool loop: works on Claude (it drops its own thinking for
  that request, documented), refused by Gemini 3.x and DeepSeek's
  Messages door. Between two servers of one dialect: refused where
  signatures are not portable. Both are written down as open.
- **What would make this rule wrong.** A server for which an empty text
  block or an empty assistant turn MEANS something the model must see.
  None was found in 14 servers or in the references; the closest is
  Gemini's empty part with a signature, which is state and is kept.
