## Why this provider

Maintainer request with a key in hand.  Meta Model API serves Muse Spark
over the three wires lm15 already speaks (Responses, Chat Completions,
Anthropic Messages — `protocols.md`: same models, same auth, same price),
plus OpenAI-shaped Files, Images and Models endpoints on the same root.
Everything it offers that lm15 has a surface for is registered; what it
offers that lm15 has no surface for (speech-to-text, token counting,
server-managed conversation state) is listed in the dossier, not guessed at.

## Reference changes (lm15-python)

1. **The Responses dialect binds.**  `OpenAILM(compat=…)` takes a preset
   name or an `OpenAIResponsesCompat` (the contract `OpenAIChatLM` and
   `AnthropicLM` already had); `OpenAIResponsesCompat.preset` reads a new
   `OPENAI_RESPONSES_PRESETS` table (the if-chain it replaces was the last
   copy of the pattern `provider-registry.md` removed from the chat
   dialect); `OPENAI_RESPONSES_PRESET_BASE_URLS`; `_COMPAT_TABLES` gains
   `openai-responses`; `registry._responses_bound`.  `AsyncOpenAILM`
   mirrors.  A base URL containing `api.meta.ai` also selects the preset
   for callers who pass only `base_url`.
2. **Three Responses compat fields and one cache-control value**, all from
   the wire:
   - `commentary_phase: "omit" | "tag"` — Meta stamps `phase: "commentary"`
     on assistant text it emits before a tool call and asks for it back
     (`protocols--responses.md` § Message phase).  Docs say the untagged
     replay is HTTP 400; live it answered 200
     (`bodies/meta.multi_turn_tool_result/2026-09-03T11-42-21Z.txt`), so
     the tag is sent for the documented quality reason.  The `meta` preset
     tags; every other preset omits (pinned OpenAI wires unchanged).
   - `edit_image_field: "array" | "indexed"` — `/images/edits` refused
     OpenAI's `image[]` key with a 400 naming `image[N]`
     (`probe-error-image-edit-array-key`); `meta` sends `image[0]`,
     `image[1]`, ….  The edit was then pixel-verified.
   - `builtin_tools: "openai" | "verbatim"` (first written as `"meta"`; renamed the same day, before any port carried it — a shape is not named after its first server) — Meta's schema names the tool
     `web_search`; OpenAI's `web_search_preview` happens to be accepted
     (200, undocumented).  The documented name is sent.  A canonical
     builtin Meta lacks goes out verbatim and the server refuses it
     (`code_execution` → 400 "did not match any supported type"), so no
     pre-wire refusal is needed.
   - `OpenAICacheControl` gains `"openai_implicit"` (both OpenAI dialects):
     `prompt_cache_key` and `prompt_cache_retention` are forwarded (both
     documented; the chat wire showed `cached_tokens: 369` on the second
     call); the explicit breakpoint mark is never placed.  A hand-sent
     mark answered 200 with no signal (`probe-cache-breakpoint-mark-raw`) —
     an undocumented field a server swallows is a silent cell (MAP-8), and
     the first version of this entry sent it.  As with `"none"`, an
     explicit `CacheConfig` is not an error: the prefix is cached regardless.
3. `OpenAIChatCompat.user_field` gains `"safety_identifier"` (Meta
   deprecates `user`; both answer 200, the documented one is sent).
4. `AnthropicCompat.thinking_format` gains `"adaptive"`: every model is the
   adaptive class (`thinking: adaptive` + `output_config.effort`), no
   model-name table; an explicit off is sent as `disabled` so the server
   refuses it loudly (400, live); `thinking_budget` raises because the
   server accepts `budget_tokens` without translating it (docs; live 200).
5. `lm15/access.py`: `META`, `META_CHAT`, `META_ANTHROPIC`, `META_ENV_KEYS`.
   `lm15/compat.py`: the three `meta` presets and base URLs.
   `tests/test_registry.py`: the third bindable dialect in the shape tests;
   `TestMeta` (7 tests: declarations, router binding sync/async, each wire's
   body, the image-edit key, the preset table).
6. Docs: providers table + a Meta note, authentication table, router
   pages, README, CHANGELOG.

No existing wire changed: the full reference suite is 1005 passed and the
harness is green on every direction.

## Not done, stated

- **Speech-to-text.**  Meta's `muse-voice-transcribe-1.0` is on Meta's own
  WebSocket / multipart protocol.  lm15 has no transcription surface
  (`EndpointSupport.speech` is text-to-speech).  That is a design pass —
  canonical types, a matrix column, every port — not a provider entry.
- **Terms review.**  See the dossier; blocks `supported`, not this entry.
- **Ports.**  Auth tables only.  The three `meta` presets, the three new
  Responses compat fields and the `openai_implicit` cache-control value are
  port work under `playbooks/port.md`.
- **`phase: "commentary"` before a provider-executed tool** is replayed
  untagged (lm15 drops `web_search_call` items and `TextPart` carries no
  provider state).  Preserving it is a canonical-type change — a design
  pass.  Live it answers 200; the documented cost is quality.
- **Evidence handling error, corrected.**  The first `image[]` failure
  receipt was deleted after the fix; the failure was re-run under a probe
  name so the evidence exists.  Likewise the original `cache-breakpoint`
  receipt was overwritten when the preset stopped sending the mark; the
  mark was re-sent by hand under `cache-breakpoint-mark-raw`.
