        <h2 id="bedrock-mantle-prereq">Prerequisites</h2>

        <p>Before using OpenAI APIs, make sure you have the following:</p>

        <div class="itemizedlist">
             
             
             
             
        <ul class="itemizedlist"><li class="listitem">
                <p><b>Authentication</b> – You can authenticate
                    using:</p>
                <div class="itemizedlist">
                     
                     
                <ul class="itemizedlist"><li class="listitem">
                        <p>Amazon Bedrock API key (required for OpenAI SDK)</p>
                    </li><li class="listitem">
                        <p>AWS credentials (supported for HTTP requests)</p>
                    </li></ul></div>
            </li><li class="listitem">
                <p><b>OpenAI SDK</b> (optional) – Install the
                    OpenAI Python SDK if using SDK-based requests.</p>
            </li><li class="listitem">
                <p><b>Environment variables</b> – Set the
                    following environment variables:</p>
                <div class="itemizedlist">
                     
                     
                <ul class="itemizedlist"><li class="listitem">
                        <p><code class="code">OPENAI_API_KEY</code> – Set to your Amazon Bedrock API key</p>
                    </li><li class="listitem">
                        <p><code class="code">OPENAI_BASE_URL</code> – Set to the Amazon Bedrock endpoint for your
                            region (for example, <code class="code">https://bedrock-runtime.us-east-1.amazonaws.com/openai/v1</code>
                            or <code class="code">https://bedrock-mantle.us-east-1.api.aws/v1</code>)</p>
                    </li></ul></div>
            </li><li class="listitem">
                <p><b>Permissions</b> – The actions you need
                    depend on the endpoint. On <code class="code">bedrock-mantle</code>, inference authorizes
                    <code class="code">bedrock-mantle:CreateInference</code>. On <code class="code">bedrock-runtime</code>, it
                    authorizes <code class="code">bedrock:InvokeModel</code> on both the inference target and your
                    account's default project, and managing stored responses authorizes
                    <code class="code">bedrock:GetInvoke</code>, <code class="code">bedrock:CancelInvoke</code>, and
                    <code class="code">bedrock:DeleteInvoke</code> on that project. For policy examples, see
                    <a href="./inference-prereq.html">Prerequisites for running model inference</a>.</p>
            </li></ul></div>

        <h2 id="bedrock-mantle-responses">Responses API</h2>

        <p>The Responses API provides stateful conversation management with support for
            streaming, background processing, and multi-turn interactions. For complete API details,
            see the <a href="https://developers.openai.com/api/reference/resources/responses" rel="noopener noreferrer" target="_blank"><span>OpenAI
            Responses documentation</span><awsui-icon class="awsdocs-link-icon" name="external"></awsui-icon></a>.</p>

        <div class="awsdocs-note"><div class="awsdocs-note-title"><awsui-icon name="status-info" variant="link"></awsui-icon><h6>Note</h6></div><div class="awsdocs-note-text"><p>Not all models support the Responses API. To see which models support the Responses API, see <a href="./models-api-compatibility.html">API compatibility</a>.</p></div></div>

         
            <h3 id="bedrock-mantle-responses-state">How the Responses API stores conversation state</h3>

            <p>The Responses API can use stored state to enable multi-turn conversations and let
                you reference previous turns through the <code class="code">previous_response_id</code>
                parameter. Storage is enabled by default but can be disabled per request through the
                <code class="code">store</code> parameter. Stored responses are scoped by Project. A response
                from one Project cannot be used as the previous response or read in a second
                Project. For more information about Projects, see <a href="./projects.html">Projects (OpenAI-compatible)</a>.</p>

            <div class="itemizedlist">
                 
                 
            <ul class="itemizedlist"><li class="listitem">
                    <p>When <code class="code">store</code> is <code class="code">true</code> (the default), Amazon Bedrock retains
                        the response, including the input and output, for 30 days. During this window
                        you can chain follow-up requests by passing
                        <code class="code">previous_response_id</code> and retrieve the response with <code class="code">GET
                        /v1/responses/<span>{</span>id}</code> on <code class="code">bedrock-mantle</code>, or <code class="code">GET
                        /openai/v1/responses/<span>{</span>id}</code> on <code class="code">bedrock-runtime</code>. After 30
                        days, the response is automatically deleted and is no longer
                        retrievable.</p>
                </li><li class="listitem">
                    <p>When <code class="code">store</code> is <code class="code">false</code>, Amazon Bedrock does not retain any
                        data from the request or response. The <code class="code">previous_response_id</code>
                        parameter cannot be used to continue the conversation.</p>
                </li></ul></div>

            <p>The default value is <code class="code">true</code> to match the OpenAI Responses API
                specification. Customers who do not want Amazon Bedrock to retain conversation data should
                explicitly set <code class="code">store</code> to <code class="code">false</code> on every request, or set the
                account's data retention mode to <code class="code">none</code>, which rejects an explicit
                <code class="code">store=true</code> outright. For more information, see <a href="./data-retention.html">Data retention</a>.</p>

            <p>Stored data is encrypted at rest and scoped to the calling AWS account's Project
                resource. The data is stored solely to service your requests and is not used or
                retained for any other purpose. On <code class="code">bedrock-mantle</code>, it is kept in the
                AWS Region the request was sent to. On <code class="code">bedrock-runtime</code>, a request that
                uses <a href="./cross-region-inference.html">cross-Region inference</a> can be
                processed in another AWS Region, and the response is stored in the Region that
                processed it — so a request that uses a global inference profile can store data
                in any commercial Region that profile routes to. If you have data residency
                requirements, use a geographic inference profile rather than a global one.</p>
         

         
            <h3 id="bedrock-mantle-responses-create">Basic request</h3>

            <p>To create a response, choose the tab for your preferred method, and then follow the steps:</p>

            <awsdocs-tabs><dl style="display: none">
                <dt>OpenAI SDK (Python)</dt><dd tab-id="openai-sdk-(python)">

                        <pre class="programlisting"><div class="code-btn-container"><div class="btn-copy-code" title="Copy"><awsui-icon name="copy"></awsui-icon></div></div><!--DEBUG: cli (python)--><code class="python "># Create a basic response using the OpenAI SDK
# Requires OPENAI_API_KEY and OPENAI_BASE_URL environment variables

client = OpenAI()

response = client.responses.create(

            <h3 id="bedrock-mantle-responses-runtime">Using the Responses API on the bedrock-runtime endpoint</h3>

            <p>The Responses API on <code class="code">bedrock-runtime</code> uses the same request and response
                format as on <code class="code">bedrock-mantle</code>, so the OpenAI SDK works against either one.
                What changes is the base URL, the model IDs, the permissions, and a small number of
                behaviors described in this section.</p>

            <p><b>Base URL and paths</b></p>
            <p>Set your base URL to
                <code class="code">https://bedrock-runtime.<code class="replaceable">region</code>.amazonaws.com/openai/v1</code>.
                The API is served on the following paths:</p>
            <div class="itemizedlist">
                 
                 
                 
                 
            <ul class="itemizedlist"><li class="listitem"><p><code class="code">POST /openai/v1/responses</code> – create a response.</p></li><li class="listitem"><p><code class="code">GET /openai/v1/responses/<span>{</span>id}</code> – retrieve a stored response.</p></li><li class="listitem"><p><code class="code">POST /openai/v1/responses/<span>{</span>id}/cancel</code> – cancel a response that is still in progress.</p></li><li class="listitem"><p><code class="code">DELETE /openai/v1/responses/<span>{</span>id}</code> – delete a stored response.</p></li></ul></div>

            <p><b>Model IDs</b></p>
            <p>Name a cross-Region inference profile as the model, not a foundation model ID. The
                OpenAI GPT models use the <code class="code">us.</code> and <code class="code">global.</code> profiles in the
                commercial Regions and the <code class="code">us-gov.</code> profiles in the AWS GovCloud (US)
                Regions — for example, <code class="code">us.openai.gpt-5.6-sol</code>. In-Region inference
                isn't available for these models on this endpoint. For the profile ID of each model,
                see its model card in <a href="./model-cards.html">Models at a glance</a>, and for how routing works, see
                <a href="./cross-region-inference.html">Route model inference requests across AWS Regions with cross-Region inference</a>.</p>

            <p><b>Permissions</b></p>
            <p>Creating a response authorizes two resources: <code class="code">bedrock:InvokeModel</code> (or
                <code class="code">bedrock:InvokeModelWithResponseStream</code>) on the inference target, as any
                inference request does, and <code class="code">bedrock:InvokeModel</code> on your account's default
                project. Retrieving, canceling, and deleting a stored response authorize
                <code class="code">bedrock:GetInvoke</code>, <code class="code">bedrock:CancelInvoke</code>, and
                <code class="code">bedrock:DeleteInvoke</code> respectively, each on the project. Individual
                response IDs are not IAM resources.</p>
            <p>Two condition keys let a policy on either resource constrain the other. The
                inference-target authorization carries <code class="code">bedrock:ProjectArn</code>, and the project
                authorization carries <code class="code">bedrock:ModelArn</code>, valued at the inference profile or
                foundation model your request named — never the destination models that a
                cross-Region profile routes to. For policy examples, see <a href="./inference-prereq.html">Prerequisites for running model inference</a>.</p>

            <p><b>Behavior differences</b></p>
            <div class="itemizedlist">
                 
                 
                 
                 
                 
                 
                 
            <ul class="itemizedlist"><li class="listitem">
                    <p><b>Requests are always synchronous.</b>
                        <code class="code">background=true</code> is rejected with a 400 error. The
                        <code class="code">store</code> parameter is unaffected and keeps its default of
                        <code class="code">true</code>, so stored, multi-turn conversations work normally.</p>
                </li><li class="listitem">
                    <p><b><code class="code">model</code> is required on every
                        request</b>, including one that supplies
                        <code class="code">previous_response_id</code>. This differs from the OpenAI Responses
                        API specification and from <code class="code">bedrock-mantle</code>, where the model can be
                        omitted and inherited from the previous response. The model is part of what
                        the request is authorized against, so it has to be named in the request
                        itself.</p>
                </li><li class="listitem">
                    <p><b>Server-side tool use and pre-configured tools aren't
                        available</b>, including <a href="./web-search.html">web search</a>.
                        Client-side tool use works on both endpoints.</p>
                </li><li class="listitem">
                    <p><b>Only the default project is supported.</b> The
                        <code class="code">OpenAI-Project</code> header is accepted only as <code class="code">default</code> or
                        as your own default project ARN; any other value is rejected. See <a href="./projects.html">Projects (OpenAI-compatible)</a>.</p>
                </li><li class="listitem">
                    <p><b>Application inference profiles aren't
                        supported.</b> A request that names one as its inference target is
                        rejected with a 400 error. System, geographic, and global inference profiles
                        work normally.</p>
                </li><li class="listitem">
                    <p><b><a href="./guardrails.html">Guardrails</a> don't
                        apply to the Responses API.</b> To apply a guardrail to a GPT model on
                        this endpoint, call the <a href="./conversation-inference.html">Converse
                        API</a> instead.</p>
                </li><li class="listitem">
                    <p><b>A stored response belongs to the AWS Region that
                        served it.</b> Retrieving, canceling, or deleting it, and continuing the
                        conversation with <code class="code">previous_response_id</code>, are all handled by that
                        Region. A response ID that can't be found — because it never existed,
                        belongs to another account, or was never stored — returns the same 404
                        error in every case.</p>
                </li></ul></div>

            <p><b>Monitoring and cost</b></p>
            <p>Because every request is synchronous, CloudWatch metrics and model invocation logging work
                for the Responses API the same way they do for the other inference APIs on this
                endpoint, including for streaming requests. Usage is attributed to the inference
                target, exactly as it is for Converse and InvokeModel — the default project is
                never the billing anchor. See <a href="./cost-management.html">Track usage and costs in Amazon Bedrock</a>.</p>
